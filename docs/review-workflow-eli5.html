誰可以做什麼？

前端隱藏按鈕只是第一層，資料庫 RPC 也會檢查角色。

🧑‍🌾

調查員／標注員

user
  • 做被指派的工作
  • 錄音、上傳、填草稿
  • 不能核准或直接寫正式結果
🎧

審聽員

audio_assessor
  • 看有音檔的案件並自取
  • 播放、判定、填原因
  • 不能核准或改正式標注
🛠️

ADMIN／助理

admin
  • 看全部、指派、改派
  • 處理追問、重判與回寫錯誤
  • 可進兩個工作台
👓

校對者

proofreader
  • 只看被指派案件
  • 保存校對進度
  • 核准或退回
📊

計畫主持人

觀察者
  • 看工作清單與核准結果
  • 發現問題通知 ADMIN

做到哪裡？

🟢 已有實作證據

  • 兩條路共用 case／version 校對層，工作台分開。
  • 審聽員角色、自取、30 分鐘 claim、token 防護。
  • 音檔判定、不可用原因、追問旗標。
  • 校對 claim、保存、核准、標音／音檔分開退回。
  • 回寫 job、冪等 key、source stamp 衝突、retry/error history。
  • 受訪者代號選填，不阻擋流程。

🟡 已設計／需正式再驗證

  • P1實際走完 ADMIN → 審聽 → 草稿 → 校對 → 核准 → Sheet。
  • P1確認 live proofreader、audio_assessor、RPC grants。
  • P1確認 TestEntries／第三期的 stamp 衝突與 retry。
  • P2整理舊音檔未審聽、舊標注 legacy 導入報告。

🔴 尚未補全

  • P0後續處理／專業會議目前只有旗標與原因，還沒有完整處理狀態、結果、處理者與時間。
  • P1直接標注／書面標注命名仍不一致。
  • P1舊版直接改標注與新版版本化流程的正式切換仍需確認。
  • P2Sheet 校對者／核准時間欄位尚未完整建立。
  • P2核准後重新修訂不在第一階段。

5 個最容易搞混的答案

問題目前答案
為什麼不只看到 TEST0001？審聽員 queue 是所有有音檔的可授權案件，再自行 claim；TEST0001 只是測試資料。
審聽完是不是已完成？不是。還要寫標音草稿、送校對、核准、回寫。
受訪者代號一定要填？不用，只是稽核參考；兩名受訪者是工作原則，不是系統 gate。
校對者能不能改內容？不能；只能檢查、保存校對決定、核准或退回。
核准後是否直接改 Sheet？先進回寫 job，再由 Places GAS 檢查 source stamp；衝突時不覆蓋。
